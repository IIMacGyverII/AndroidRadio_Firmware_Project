# Session start — read this first

Instructions for AI agents (Claude Code, Grok Build) working in **AndroidRadio_Firmware_Project**.

> **Mirror rule:** `CLAUDE.md` and `GROK.md` are byte-identical copies, one per agent. Edit either, then copy it over
> the other in the same commit. Verify with `git diff --no-index CLAUDE.md GROK.md` (no output = in sync).

## What this repository is

The firmware home for the Android walkie-talkie phones the project supports: stock and modified module images with
their manifests, the signed catalogue SignalDeck reads, device and module facts, and an index of the research. It
is public. Research and bench work happen in `phonedmrapp` (`radio_firmware/HANDOFF.md` is the bench mailbox);
the app is `SignalDeck`. This repository records results; it does not run the bench.

## Layout and the rules per folder

| Folder | Rule |
|---|---|
| `firmware/<device>/<tag>/` | `<tag>.bin`, `manifest.json`, `README.md`. The manifest's `sha256`, `md5` and `size` must match the file (`python scripts/build_catalog.py --check`). A modified image names the phonedmrapp commit and build script that reproduce it byte for byte, and the `results.md` section that measured it. A stock image names the stock app package, version and asset path it was taken from and the asset's hash. |
| `catalog/firmware.json` | Generated by `scripts/build_catalog.py` from every manifest and every `devices/*/variants.json`; never edited by hand. CI rebuilds it and fails the push if the committed file differs or the signature does not verify. Bump `serial`, sign with `scripts/sign_catalog.py` (ECDSA P-256 / SHA-256, base64 DER, the SignalDeck profile-list key at `~/.signaldeck/profile_signing_key.pem`, never in any repository), commit `firmware.json` and `firmware.json.sig` together. |
| `devices/<vendor>-<model>/` | `README.md` + `device.json` (schema `devices/device.schema.json`) + `variants.json` (`devices/VARIANTS.md`; grows from the "Firmware variant seen" issue form). Say for every fact whether it was measured on the phone, read from the stock app, or inferred. `signaldeckProfile` is SignalDeck's profile id when one exists. |
| `modules/<module>/` | Chip and firmware facts that hold across phones (addresses are per image; say which image). |
| `research/` | Pointers and summaries only; the full documents stay in phonedmrapp. |

## Hard rules

- **Nothing that identifies a person:** no callsigns, DMR IDs, locations, phone serials, APRS passcodes, IP
  addresses, in any file or commit message. Bench logs quoted here use bench callsigns.
- **No band-limit or power patches**, and no image that changes them, ever.
- **Only stock images and released images are committed here** (owner, 2026-10-25). Bench and beta images stay in
  phonedmrapp (`radio_firmware/build/`) until the owner releases them. A released image is listed only when it is
  reproducible from a named commit and script, measured with the results linked, and its base image's stock copy is
  in this repository.
- **The factory image for a device is never removed or altered.** It is the restore path for every user of that device.
- **Hashes are the identity.** A file whose hash is not in the catalogue is not an image, whatever its name says.
- Commit only what you changed (`git add <paths>`); never `git add -A`.

## Keys

Private signing keys are never in any repository (`catalog/KEYS.md`); the public keys and their fingerprints are published in `catalog/` and checked by `scripts/verify_catalog.py`. **Two keys since 2026-10-30 (owner):** catalogue serials below 6 are signed with the shared profile-list key (`public_key.pem`); from serial 6, the first catalogue with a released image (FW57), with the firmware key (`public_key_firmware.pem`, private half `~/.signaldeck/firmware_signing_key.pem`). `scripts/keys.py` holds the switch serial; `sign_catalog.py` and `verify_catalog.py` pick the key from it. SignalDeck carries both public keys from beta.22. Rotation is written down in `KEYS.md` and never done silently.

## Where the facts come from

- Device facts: SignalDeck device reports (Run all checks) and the stock app's code, read offline. Nothing from a
  report that identifies its owner is copied here.
- Module facts: `phonedmrapp/docs/deep-dive/19-firmware-modification-plan.md`,
  `phonedmrapp/docs/grok-deep-dive/11-firmware-fw0-results.md`, `phonedmrapp/radio_firmware/results.md` and
  `reviews.md`.
- Loader contract: `phonedmrapp/radio_firmware/plan-loader-safety.md`; the user-facing version is `SAFETY.md` here.
- Port to a new phone: `phonedmrapp/radio_firmware/plan-port-automation.md`.

## When you add or change something

1. Manifest and README for the image or device, with provenance.
2. `python scripts/build_catalog.py --check` passes.
3. If the catalogue changed: bump `serial`, sign, commit both files.
4. `CHANGELOG.md` entry, newest first.
5. Mirror `CLAUDE.md` ↔ `GROK.md` if you edited either.
